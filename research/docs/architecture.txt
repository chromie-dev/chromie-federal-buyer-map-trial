AGENCY INTELLIGENCE, NAVY TRIAL: ARCHITECTURE
==============================================

One sentence: public documents about a buyer are saved with their provenance, read into dated
events under the office they name, loaded into the production schema, and read back as a score,
a weekly diff and a short list of actions, each of which points at the documents behind it.

Every box below is one tool in research/tools/ and one stage of pipeline.py, so the diagram is
also the run order.  The rules and the schema do not know the Navy; the agency sits in the organization
seed, the registry, the saved documents and a few named constants at the top of the tools (the department
id, the pilot offices, the feeds), so the same chain runs for another agency once those exist (document 14).


0. LEGEND
---------

  [C]  connector      a known URL read on a schedule; no judgment; a document is saved with its
                      url, sha256, retrieved_at and path in documents_manifest.jsonl
  [A]  agent + lints  an LLM call with a JSON schema, answered once and kept as a cassette under
                      the hash of (prompt, text, schema); deterministic lints drop or repair what
                      the model returns; a rebuild replays cassettes and never pays twice
  [R]  rules          plain code with a self-check; exact decimals where a number is shown
  [S]  store          a file under research/ or a table in the database
  ---  file boundary  every stage writes a file the next one reads, so any stage runs alone

2. DATA SOURCES: EVERY REGISTERED ROW
-------------------------------------

Every source is one row in source_registry.json: publisher, official url, access mode, cadence,
what it can answer, what it cannot, the restriction met, and the date it was verified.  The
registry loads as gov_procurement_sources, so a row in the database can always be traced to a
registered source.  Status is from source_status.json (events in the corpus,
documents in the manifest).  A family is one kind of statement; the bar a cell must reach is
THREE INDEPENDENT FAMILIES.

   how read      api = documented or public JSON endpoint; webpage = HTML saved as fetched, read
                 as its Markdown rendering (markdown.py); pdf, spreadsheet, export = files;
                 manual = login or vendor account needed
   route         direct from this network, or through the hosted browser where the host
                 refuses automation from a non-US address (Akamai 403, firewall stubs)

5. LOAD (the production schema, nothing else)
---------------------------------------------

   schema      schema_subset.py    the loaded-table subset of the production schema
   layers      agency_layers_sql.py emits layers.sql in dependency order:

        gov_organizations ............ department, commands, PEOs, program offices, contracting
                                       offices (ids like command:navwar, pmw:101)
        gov_procurement_sources ...... the registry
        gov_needs, gov_requirement_revisions
                                     forecast rows and what changed between releases
        gov_intelligence_evidence .... one row per saved document actually cited
        agency_brain_items ........... every dated event: section (check constraint),
                                       event_type, event_date, source_tier, source_provider,
                                       primary_organization_id, source jsonb (url, sha256,
                                       retrieved_at, path)
        gov_contacts, gov_contact_positions
                                     people and their dated positions (role check constraints)
        gov_organization_relationships
                                     edges with source, source_ref, observed_at, confidence;
                                       an edge without them is refused

   database    drop, create, schema.sql, layers.sql with ON_ERROR_STOP.  A row that breaks a
               constraint fails the whole load, so a bad vocabulary never half-applies.
   graph       graph_export.py writes the organization graph the program-office resolver reads.

----------------------------------------------------------------------

   backtest [R]  freeze, label [A], run, show: the families in place before each notice or award


7. READ BACK: PULSE (what to do this week)
------------------------------------------

   cell = one requirement under one office (a forecast row or a notice with its aliases)

   score = 40 * families + 20 * recency + 20 * persistence + 20 * proximity      exact decimals
             families    distinct families seen, capped at five
             recency     how recently the newest statement came
             persistence how many distinct months carry a statement
             proximity   how near the forecast's stated solicitation is, with a slip flag
                         when a later release moved it

   reports beside the score, never inside it:
             novel_families   families first seen in the last 90 days
             momentum         events in the last quarter against the quarter before
             vendors          who holds the cell's contracts, by count of base awards
             contacts         the people the record ties to the office (meet_office only)

   week diff  what changed per office since the last saved pulse, in the counting register
   actions    a closed list: meet_office, attend_event, research_program, find_partner,
              monitor_forecast, watch_expiration, track_person; each names its evidence rows;
              duplicates collapse by action, office and evidence


8. THE PROVENANCE THREAD (why did the system believe X on date D)
-----------------------------------------------------------------

   document bytes under data/raw
        |  sha256
        v
   manifest line: url, sha256, retrieved_at, path        (documents_manifest.jsonl)
        |  path
        v
   evidence row                                          (gov_intelligence_evidence)
        |  id
        v
   brain item: event_date, family, office, text, source  (agency_brain_items)
        |
        v
   backtest show, pulse action: one line per family, the document and the day it became
   available

   Every number a customer sees recomputes from the rows beneath it.  There is no field that
   was typed by hand between a document and a score.
